Altered Blood+

  • itch.io
  • Github

A boomer shooter with fast-paced FPS gameplay, developed in UE5 as my second project working at TrueWorld Studios.

One major system I worked on was an online task queue that handles online leaderboard related requests and can be extended to handle online achievements. Each online task is encapsulated in a UObject that inherits from a base task that provides functionality for executing the task and being managed in the queue system.


DECLARE_DYNAMIC_MULTICAST_DELEGATE(FS1_OnlineTaskComplete);

UCLASS(Abstract)
class ALTEREDBLOOD_API US1_BaseOnlineTask : public UWorldObject
{
	GENERATED_BODY()

public:

	UFUNCTION(BlueprintCallable)
	virtual void StartTask() PURE_VIRTUAL(US1_BaseOnlineTask::StartTask, );

    // for the queue to know when the currently executing task is complete
	UPROPERTY(BlueprintAssignable)
	FS1_OnlineTaskComplete OnlineTaskCompleteEvent;

    // for other subscribers to know when the task is cancelled
	UPROPERTY(BlueprintAssignable)
	FS1_OnlineTaskComplete OnlineTaskCancelEvent;

	UFUNCTION(BlueprintCallable)
	void Cancel();

	UFUNCTION(BlueprintCallable)
	void SetId(FGuid Id);

protected:
	UFUNCTION(BlueprintImplementableEvent)
	void PostCompleteTasks();

	UPROPERTY(BlueprintReadOnly, VisibleAnywhere)
	FGuid TaskId;

	virtual void OnTaskCompleted();

	virtual void Cleanup();

	virtual void OnTaskFail();
};

The online tasks are written in C++, since Unreal does not expose global leaderboard reading to blueprints. The online task queue system itself is created in blueprints as it is not very complicated - tasks can be submitted to be queued, which returns a guid. Once the task fires off its completed delegate, it is removed from the queue and the next task is dequeued and started. The guid can be used to cancel any task in the queue that has not yet been started.

A task queue that uses delegates to handle the queue was chosen over an async implementation (which Unreal's leaderboard blueprint nodes use) as async tasks run on Unreal's game thread and will not progress while the game is paused. Since leaderboard reads and writes are performed primarily while UI is open, it needs to be able to progress while the game thread is paused.

Individual online tasks provide additional delegates to subscribe to that sends out whether the task succeeded and any information the task was meant to retrieve, allowing flexibility. As many online task types as required can be defined, and they can also be defined in blueprints for the ease of the design team.
